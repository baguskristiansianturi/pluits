# Stories — Project Delivery

## Project register
Maintain one record per feature with: ID, scope, owner, priority, dependency, status, target milestone, source paths, PR/commit, test evidence, and rollout status.

## Delivery stages
1. Discovery and requirements.
2. Product/UX design and acceptance criteria.
3. Technical design and threat/privacy review.
4. Frontend prototype and responsive UI/UX validation.
5. Backend/API/data implementation (when in scope).
6. Module and integration tests.
7. Accessibility, performance, and security review.
8. Staged release, monitoring, and rollback readiness.

## Status vocabulary
- PROPOSED
- IN-DESIGN
- DESIGN-REVIEW
- APPROVED
- IN-DEVELOPMENT
- IN-TEST
- READY-FOR-RELEASE
- RELEASED
- DEPRECATED

A folder or mock UI does not imply RELEASED. Every status change must include dated evidence.
